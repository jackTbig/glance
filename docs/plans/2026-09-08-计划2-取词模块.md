# 计划 2：取词模块 `crates/text-capture`

**Goal:** Windows 上三种取词方式：划词（剪贴板）、悬停（无障碍接口 UIA，失败自动截图 OCR）、截屏区域 OCR。OCR 引擎可插拔。

**Architecture:** 纯同步库，不依赖 GUI 框架。对外只暴露三个入口函数与一个 `OcrEngine` trait；Windows 专有实现全部关在 `#[cfg(windows)]` 里。

**Tech Stack:** `uiautomation` 0.25、`windows` 0.62（WinRT：Media_Ocr / Graphics_Imaging）、`windows-sys` 0.61（Win32：SendInput / 剪贴板 / BitBlt）、`image` 0.25。

**已验证（2026-09-08 本机实测）：**
| 项 | 结果 |
|---|---|
| Windows OCR 可用语言 | 只有 zh-Hans-CN，**没有英文包**（装它要管理员权限，Jack 未提权） |
| 中文引擎识别英文 | 78 ms，可读但会插空格、`It`→`lt`、`-`→`一` |
| UIA `element_from_point` | 0–35 ms，能取到真实段落文本 |
| Chrome 窗口 | 无 TextPattern（正常：浏览器由插件负责） |

### Task 2：OCR 引擎

- [ ] Step 1：`src/ocr.rs`

```rust
#[derive(Debug, Clone, PartialEq)]
pub struct OcrLine { pub text: String, pub rect: (i32, i32, i32, i32) }  // x, y, w, h
#[derive(Debug, Clone, PartialEq, Default)]
pub struct OcrResult { pub lines: Vec<OcrLine>, pub text: String }

pub trait OcrEngine: Send + Sync {
    fn name(&self) -> &str;
    fn recognize(&self, img: &image::RgbaImage) -> anyhow::Result<OcrResult>;
}

#[cfg(windows)] pub struct WindowsOcr { engine: windows::Media::Ocr::OcrEngine, lang: String }
#[cfg(windows)] impl WindowsOcr {
    /// 按用户语言建；失败则挑第一个可用语言
    pub fn new() -> anyhow::Result<WindowsOcr>
    pub fn language(&self) -> &str
    pub fn available_languages() -> Vec<String>
}
/// 默认引擎：Windows 自带；以后加 RapidOCR 在这里选
pub fn default_engine() -> anyhow::Result<Box<dyn OcrEngine>>
```
实现要点：`RgbaImage` → `SoftwareBitmap`（`BitmapPixelFormat::Bgra8` + `Premultiplied::None`，逐像素 RGBA→BGRA 写进 `IMemoryBufferByteAccess`）；异步用固有方法 `.join()`，**不要 import `Async` trait（未公开导出）**。

### Task 4：划词

- [ ] Step 1：`src/clipboard.rs`

```rust
/// 取当前选中的文本：保存剪贴板 → 送 Ctrl+C → 轮询剪贴板序列号变化（最多 400 ms）→ 读文本 → 还原剪贴板
```

### Task 5：UIA 取词

- [ ] Step 1：`src/uia.rs`

```rust
pub struct UiaCapture { auto: uiautomation::UIAutomation }
impl UiaCapture {
    pub fn new() -> anyhow::Result<UiaCapture>
    /// 取屏幕坐标处的段落文本；拿不到返回 Ok(None)
    pub fn text_at(&self, x: i32, y: i32) -> anyhow::Result<Option<String>>
    /// 该点所属进程的可执行文件名（小写，如 "notepad.exe"），用于进程例外
    pub fn process_at(&self, x: i32, y: i32) -> anyhow::Result<Option<String>>
}
```
顺序：`element_from_point` → `TextPattern::get_range_from_point` → `expand_to_enclosing_unit(Paragraph)` → `get_text(4000)`；没有 TextPattern 时退回元素的 `Name`（长度 2..=500 才用）。整个调用包 200 ms 超时保护：UIA 对无响应窗口会卡住，**必须放到独立线程里跑并用通道超时**，否则会卡住 UI 主线程。

- [ ] Step 2：测试：`UiaCapture::new()` 成功；桌面根元素坐标不 panic（真实取词进手工清单）

```rust
pub enum Source { Clipboard, Uia, Ocr }

    pub fn ocr_language(&self) -> Option<String>
}
```

## 已知限制（写进交付文档）
- 本机 Windows OCR 只装了简体中文包，识别英文有瑕疵（插空格、`It`→`lt`）。装 `Language.OCR~~~en-US~0.0.1.0` 需要管理员权限，留给 Jack 提权后执行；截屏场景的提示词已要求模型先纠错再翻译，可缓解。
- 划词还原剪贴板只还原文本格式，复制图片时会丢失原剪贴板内容。
- 浏览器窗口通常没有 TextPattern，桌面悬停在浏览器里会退到 OCR；浏览器内的翻译由 Chrome 插件负责，不受影响。
