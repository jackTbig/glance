# live-caption 设计文档 —— 桌面悬浮实时字幕翻译（英→中）

日期：2026-09-03　状态：已与 Jack 逐段确认　项目根：`D:\My_data\Claude\live-caption\`

## 一、目标与边界

**目标**：一个常驻桌面、置顶悬浮的字幕窗，把电脑里正在播放的英文语音（Teams / Zoom / 网页视频等）实时转成"英文原文 + 中文译文"双语字幕。自用、单机、Windows 11。

**关键约束**（均为 Jack 拍板）：
- 声源只取系统内录（WASAPI loopback），不做麦克风。
- 语音识别在本机完成（Intel Arc 140T 核显），会议音频不出本机；翻译走云端 claude CLI 常驻会话，只有识别出的英文文本出网。
- 技术栈 Rust 全栈，理由是常驻工具要小、要稳、要一键起；性能真正的瓶颈在 GPU 推理与网络，第 0 步用基准验证识别后端。
- 字幕显示双语对照，不做历史面板。

**延迟目标**：说完一句到英文上屏 ≤ 2 秒，中文上屏 ≤ 4 秒。

**明确不做**（第一版）：麦克风采集、多语种自动检测、历史面板、系统托盘、自动更新、Silero VAD。

## 二、架构

单个 Rust 二进制，四条工作线程 + 界面线程，用有界通道串联：

```
[采集线程] --PCM 16k mono f32--> [切句线程] --音频段--> [识别线程] --(段号,英文)--> [界面]
                                                                  \--(段号,英文)--> [翻译线程] --(段号,中文)--> [界面]
                                                                                                          \--> [记录文件]
```

### 2.1 采集线程
- crate `wasapi`（HEnquist），以 loopback 模式打开默认播放设备。不用 cpal，其 loopback 支持历史上加了又去。
- 设备原生格式（常见 48 kHz 立体声）就地混单声道、重采样到 16 kHz（线性插值即可，语音识别对此不敏感），推入环形缓冲。
- 默认设备变化或设备拔出：报错，每 2 秒重试重开，状态点转红并显示"音频设备重连中"。

### 2.2 切句线程（VAD）
- 能量门限法：按 20 ms 帧算 RMS，超过门限计为有声。
- 规则：有声开始后累积；静音连续 ≥ 500 ms 切段；单段最短 1 s（更短的丢弃，视为噪声）、最长 8 s（超长强制切）。
- 门限、静音时长、最短最长均在 `config.toml` 可调。
- 不引入 Silero 模型：内录音质干净，能量法先用；切句效果差再升级（接口保持"输入 PCM 流、输出音频段"不变，便于替换）。

### 2.3 识别线程
- whisper-rs（`vulkan` 特性）进程内加载 ggml large-v3-turbo（`local-asr\ggml-large-v3-turbo-q5_0.bin` 现成权重，只读引用，配置里可改路径）。
- 参数：language=en，task=transcribe，no_timestamps，上一段的英文文本作 initial prompt 保持术语连贯。
- 每段出结果后立刻发两份：界面 + 翻译队列。空结果或纯标点结果丢弃。
- 识别异常：记日志、跳过该段，不阻塞后续。
- **后端定案依据是第 0 步基准**：若 whisper.cpp Vulkan 在本机比 OpenVINO int8 慢一倍以上，则识别改为 OpenVINO 侧车进程（复用 local-asr 的 venv 与 HTTP 协议），Rust 侧只换识别线程的实现，其余不变。

### 2.4 翻译线程
- 启动 `claude -p --input-format stream-json --output-format stream-json --verbose` 子进程常驻，标准输入逐句送英文，标准输出收中文。
- 系统提示固定："你是会议同传，把输入的英文逐句译成简体中文，只输出译文，不加任何解释。" 关闭全部工具（具体参数在第 0 步核实）。
- 模型名可配，默认 sonnet；追求速度可切 haiku。
- 会话每累计 60 句重启一次，避免上下文过长拖慢响应。
- 单句超过 8 秒无回应或子进程退出：杀掉重启新会话，该句显示"（翻译超时）"，后续继续。
- 翻译队列有界 10 句，积压超限丢最旧的，保证字幕跟得上现场；积压 > 3 句时状态点转黄。

### 2.5 界面线程
- 只收两种消息：某段英文到了、某段中文到了；按段号对齐。
- 每段落盘一行到 `transcripts/YYYY-MM-DD_HHMM.md`：`[HH:MM:SS] EN ... / ZH ...`。

## 三、悬浮窗与交互

- egui/eframe：无边框、置顶、半透明深色背景（透明度可调），默认贴屏幕下沿居中，宽约屏幕 60%，高度随两到三行自适应。按住任意处拖动；位置尺寸记入配置，下次复原。
- 字幕：只显示最近 2 段，每段上行英文、下行中文。英文已到中文未到时中文行显示淡色"…"；新段出现旧段上滚淡出。识别中的段不显示半成品。
- 悬停右上角出现按钮条：暂停/继续、字号加减、透明度、鼠标穿透开关、打开记录文件、退出。
- 鼠标穿透后用全局热键 `Ctrl+Alt+C` 切回。
- 状态点：绿=正常，黄=翻译积压 > 3 句，红=某环节挂了并显示一句原因。
- `config.toml`（exe 同目录）：模型路径、claude 模型名、字号、透明度、窗口位置尺寸、VAD 参数；改完重启生效。

## 四、日志与错误处理汇总

| 环节 | 故障 | 处理 |
|---|---|---|
| 采集 | 设备拔出/默认设备切换 | 每 2 s 重试重开；红点提示 |
| 识别 | 单段推理异常 | 记日志、跳过 |
| 翻译 | 子进程退出 / 单句 > 8 s | 重启子进程；该句标"（翻译超时）" |
| 翻译 | 队列积压 > 10 | 丢最旧；> 3 黄点 |
| 通用 | 线程 panic | 界面红点显示环节名与原因，进程不退出 |

日志：`logs/live-caption.log`，按天滚动保留 7 天。

## 五、测试

- **单元**：切句器（静音流不出段 / 连续语音到 8 s 强制切 / 1 s 以下丢弃）、重采样（48k→16k 长度与频率）、翻译协议解析。
- **集成**：用一个假的子进程脚本冒充 claude，验证逐句对应、超时重启、60 句轮换；识别线程用 `local-asr\test-10s.wav` 做端到端断言（含关键词）。
- **人工验收**：播放一段英文演讲视频，观察延迟是否达标、切句是否自然、译文是否连贯。

## 六、第 0 步：基准验证（一小时上限，先于一切开发）

核实四件事，结果写入本文档附录 A：
1. 本机 Vulkan SDK、LLVM/clang（bindgen 需要）、CMake 是否齐全；whisper-rs `vulkan` 特性能否编译。
2. whisper.cpp Vulkan 版 `bench` / `whisper-cli` 对 `test-10s.wav` 的耗时与识别文本，对照 OpenVINO 8080 服务（large-v3 int8）同一音频的耗时与文本。
3. claude 子进程 stream-json 单句翻译往返时间，以及关闭工具的正确参数。
4. `wasapi` crate loopback 在本机能否拿到 Teams/浏览器播放的声音。

**判定**：Vulkan 耗时 ≤ 2 × OpenVINO → 进程内 whisper-rs；否则识别走 OpenVINO 侧车。
