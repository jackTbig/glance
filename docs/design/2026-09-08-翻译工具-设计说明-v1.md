## 1. 目标与边界

自用版翻译工具，覆盖桌面任意窗口与 Chrome 浏览器，后端接大模型。三项核心能力：

| 能力 | 桌面端（任意窗口） | Chrome 插件 |
|---|---|---|
| 整页翻译 | 不做（浏览器由插件负责） | 手动触发，双语对照，可切仅译文 |
| 悬停翻译 | 修饰键 + 悬停，UIA 取词，失败自动截图 OCR | 修饰键 + 悬停段落 |
| 划词翻译 | 选中弹小图标 或 快捷键 | 选中弹小图标 或 快捷键 |
| 截屏翻译 | 快捷键框选区域，OCR 后整段翻译 | 不做 |

附加功能：术语表、面板钉住与拖拽。**不做**：输入框翻译、翻译历史、站点自动规则、本地 Ollama 后端、PDF/EPUB 阅读器、语音相关。

语言方向：目标固定简体中文；源语言自动识别，默认按英文处理；中文段落原样跳过。

差异化定位：自用，不追求超越竞品；隐私上 Key 与内容只经桌面端与所选大模型服务，插件本身零 Key。

## 2. 与 live-caption 的关系

**只共享代码，产品各自独立。** 翻译核心抽为独立 crate 放在本仓库，live-caption 改为依赖它，其余保持原样（独立仓库、独立 exe、独立安装包、独立配置文件）。

- 两个进程互不依赖：任一未运行不影响另一方。
- 本项目不带 whisper、Vulkan、CMake、LLVM、Ninja 等语音编译环境。
- 后端配置（Base URL / Key / 模型）首次运行时从 live-caption 配置文件导入一次，之后各自维护，不做实时共享。
- 改 live-caption 属跨项目改动，收尾必须在其 `CLAUDE.md` 留交接（见第 9 节）。

## 4. 翻译核心 `crates/ai-translate`

### 4.1 搬迁部分
从 `live-caption/src/translate.rs` 1–501 行搬入：claude CLI 后端、codex 后端、OpenAI 兼容后端及其会话轮换、超时、上下文句子逻辑。公开接口不变：`Translator::new(cfg)` / `.translate(text, on_delta)`。

### 4.2 新增部分
- **并发池**：OpenAI 兼容后端加信号量限并发，默认 8，可配。claude / codex 后端固定串行（常驻子进程，每路约 300 MB）。
- **指数退避重试**：网络错误与 429/5xx 重试 3 次，间隔 1s / 2s / 4s，429 优先读 `Retry-After`。
- **批量请求**：`translate_batch(items) -> Vec<Result<String>>`，一次请求打包多段，段间以编号分隔，解析回包按编号还原；缺段或错位视为该段失败。
- **HTML 标签保护**：行内标签（a / strong / em / code / span 等）替换为 `⟦1⟧…⟦/1⟧` 占位符后送翻译，回包还原；占位符丢失则该段判失败。
- **术语表**：TOML 配置 `[[glossary]] src = "..." dst = "..."`，命中则以「术语对照」形式附进 prompt；不做硬替换。
- **场景 prompt**：四套模板，分别针对整页（批量、保占位符）、划词（短句、可含解释）、悬停（段落）、截屏（OCR 文本纠错 + 翻译），变量：源语言、目标语言、术语对照、上下文。
- **场景与后端映射**：`scene -> backend + model`，整页固定 openai，其余可选三后端，默认全部 openai + DeepSeek deepseek-chat。

### 4.3 错误处理
- 单段失败不影响整批其它段。
- 重试耗尽返回错误，由调用方决定展示（插件标红可点重翻；桌面弹窗显示错误文字）。
- claude / codex 子进程崩溃自动重启一次。

### 4.4 测试
单元测试覆盖占位符替换与还原、批量编号解析、术语表注入、退避计算。集成测试起 `tests/mock-llm` 假服务，验证并发上限、429 退避、部分失败、超时；不依赖真实 Key。

## 5. 取词 `crates/text-capture`

- **划词**：保存剪贴板 → 模拟 Ctrl+C → 读取文本 → 还原剪贴板。选区为空或与上次相同则忽略。
- **UIA 取词**：`IUIAutomation::ElementFromPoint` 取鼠标下元素，`TextPattern.RangeFromPoint` 扩展到段落取文本；无 TextPattern 则取元素 Name；文本为空或超过 2000 字符视为失败。
- **截屏 OCR**：截取指定区域（悬停为鼠标周围 600×200 像素，截屏翻译为用户框选区域），送 OCR 引擎。引擎接口 `trait OcrEngine { fn recognize(&self, image) -> Vec<Line> }`，默认实现调 Windows.Media.Ocr（Windows 10+，中英），预留 RapidOCR 实现位。
- **悬停策略**：UIA 优先，失败自动截图 OCR；两者都失败静默不弹。
- 测试：划词与 UIA 依赖真实窗口，进手工验收清单；OCR 引擎用固定图片做单元测试。

## 6. 桌面端 `apps/desktop`

### 6.1 组成
- **托盘**：菜单含 设置 / 暂停取词 / 退出。沿用 live-caption 的 tray-icon 原生菜单写法，不挂 muda。
- **全局钩子**：低级鼠标钩子（WH_MOUSE_LL）检测选中结束（鼠标抬起且有拖动）与悬停停留；global-hotkey 注册划词、截屏、显示/隐藏面板三个快捷键。
- **触发规则**：
  - 划词：选中结束 → 小图标出现在选区右下角，2 秒不点自动消失；点图标或按快捷键 → 弹窗。小图标可在配置关闭。
  - 悬停：按住修饰键（默认 Alt，可配）且鼠标停留 300 ms → 取词 → 弹窗。
  - 截屏：快捷键 → 全屏遮罩框选 → OCR → 弹窗显示识别原文与译文。
  - 进程名例外列表：命中的应用不弹图标、不响应悬停（快捷键仍有效）。
- **弹窗**：egui 多视口子窗口，透明置顶、`WS_EX_NOACTIVATE` 不抢焦点、自绘圆角、跟随光标出现且不出屏幕边界（多显示器收敛到光标所在屏）。译文流式显示。默认失焦或鼠标离开 500 ms 即关；点「钉住」后变为可拖动的持久面板，右上角关闭。
- **设置窗**：后端与模型按场景分别选、快捷键与修饰键、小图标开关、进程名例外、术语表编辑、OCR 引擎、本地服务端口。

### 6.2 配置
TOML，路径规则沿用 live-caption（开发目录 vs `%APPDATA%\<正式名>\config.toml`），`CONFIG_VERSION = 1` 带迁移函数。首次运行若无配置且存在 live-caption 配置，导入其 `[translate]` 段的 openai_base_url / openai_api_key / openai_model / claude_bin / claude_model / codex_bin / codex_model。

### 6.3 本地 HTTP 服务
- 只绑 `127.0.0.1`，端口默认 42731，可配。
- 校验请求头 `Origin` 必须为本插件的 `chrome-extension://<id>`，其余一律 403。
- 接口：
  - `GET /v1/health` → 版本、当前后端、并发上限
  - `POST /v1/translate` 请求 `{ scene, items: [{ id, text }], context? }`，响应 `{ results: [{ id, text | error }] }`
  - `POST /v1/translate/stream`（划词、悬停用）SSE 流式返回单条译文
- 并发控制在服务端，插件只管发；服务端按场景映射选后端。

### 6.4 编译踩坑（照抄 live-caption）
wgpu 透明黑底必须 glow；tray-icon 不挂 muda；`windows_subsystem="windows"` 下不能 `cmd /C start`；PowerShell 脚本必须 ASCII。

## 7. Chrome 插件 `extension/`

MV3，TypeScript，Vite 打包。开发者模式加载，不上商店。

- **background（service worker）**：唯一与本地服务通信的模块，`host_permissions` 声明 `http://127.0.0.1:*/`；转发 content script 的请求；服务不可达时向页面返回「翻译工具未运行」。
- **content script**：
  - 整页：快捷键或点插件图标触发。收集块级文本元素（p / li / h1–h6 / td / blockquote / dd 等，跳过 script / style / pre / code / 已译节点 / 不可见节点），行内子标签交给核心做占位符保护。每请求 10 段，并行发送，服务端限并发。译文插入原段之后，同样式、带 class 便于主题；再触发一次切换「双语 / 仅译文 / 原文」。动态加载内容用 MutationObserver 增量翻译。
  - 悬停：修饰键（默认 Alt，可配）+ 鼠标停在块级元素 300 ms → 该段单独翻译并插在下方。
  - 划词：选中结束弹小图标（可关）或快捷键 → 页内浮层面板，流式显示；可钉住拖动。
- **options 页**：服务端口、快捷键、修饰键、小图标开关、默认显示模式。不含任何 Key 或模型设置。
- **测试**：Playwright 以 `--load-extension` 加载，访问 `tests/e2e/pages/` 固定页面，本地服务指向 mock-llm，断言整页段数、译文插入、仅译文切换、悬停插入、划词面板出现、服务未运行提示。

## 10. 实施顺序
1. `git init`，建 workspace 骨架，mock-llm。
2. `ai-translate`：搬迁 → 新增能力 → 测试 → live-caption 切换依赖并回归。
3. `text-capture`：划词 → UIA → OCR。
4. 桌面端：托盘 + 配置 → 弹窗 → 划词 → 悬停 → 截屏 → 设置窗 → 本地服务。
5. 插件：background + 服务对接 → 整页 → 悬停 → 划词 → options → Playwright。
6. 安装包、验收清单、自测、交付。

每步一份实施计划，由 writing-plans 产出。
